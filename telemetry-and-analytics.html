Ecompapi / EVENT PROCESSING & TIME SERIES

From activity events to useful analytics.

A Kafka ingestion path and time-series reporting layer for a desktop productivity tracker.

Simplified conceptual flow. Describes the implementation approach, not a complete production topology.

01

The constraint

Desktop agents submitted employee activity data at minute-based intervals, including foreground and background application activity. Repeated events created a growing time-series dataset, while the product needed productivity summaries across employees and time windows.

02

What I owned

I built the Kafka-based telemetry processing approach and the TimescaleDB reporting mechanisms, using time buckets, aggregate views, and compression. Screenshots were stored separately from telemetry records.

03

Decouple ingestion and analysis

Kafka handled incoming telemetry in an asynchronous processing path. This separated event collection from the work required to prepare and serve analytics.

04

Read summaries instead of raw history

The reporting layer combined TimescaleDB continuous aggregates with manually refreshed materialized views. Time buckets organized activity into reporting windows, reducing the amount of raw history that needed to be processed for repeated summaries.

05

Manage growing history

Compression supported management of the accumulating time-series data. Keeping screenshots outside the telemetry records also separated image storage from the structured data used in reporting.

06

Outcome

The system supported ongoing telemetry ingestion and aggregate productivity reporting. This case study describes the implemented approach without claiming an unmeasured throughput or compression ratio.
